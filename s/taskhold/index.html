Set up in your client

Claude Code

Run this in a terminal:

claude mcp add --transport http taskhold https://taskhold.com/api/mcp

Claude Desktop

Open Settings → Connectors → Add custom connector and paste this URL:

https://taskhold.com/api/mcp

Or bridge it through mcp-remote in claude_desktop_config.json (needs Node.js):

{
  "mcpServers": {
    "taskhold": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://taskhold.com/api/mcp"
      ]
    }
  }
}

Cursor

Add to Cursor

Or add it to ~/.cursor/mcp.json (or .cursor/mcp.json in a project):

{
  "mcpServers": {
    "taskhold": {
      "url": "https://taskhold.com/api/mcp"
    }
  }
}

VS Code

Add to VS Code

Or add it to .vscode/mcp.json:

{
  "servers": {
    "taskhold": {
      "type": "http",
      "url": "https://taskhold.com/api/mcp"
    }
  }
}

Or from a terminal:

code --add-mcp '{"name": "taskhold", "type": "http", "url": "https://taskhold.com/api/mcp"}'

Windsurf

Add it to ~/.codeium/windsurf/mcp_config.json:

{
  "mcpServers": {
    "taskhold": {
      "serverUrl": "https://taskhold.com/api/mcp"
    }
  }
}

Other clients

Most clients accept this shape. The endpoint is:

https://taskhold.com/api/mcp
{
  "mcpServers": {
    "taskhold": {
      "type": "http",
      "url": "https://taskhold.com/api/mcp"
    }
  }
}

If it does not connect

  • Restart the client after editing a config file, and keep keys out of files you commit.
  • If the tools do not appear, open the client's MCP log: a 401 means the credentials were not accepted, and a timeout means the server did not answer.

taskhold_begincan modifyStart work in one call: files a new task (or takes an existing one with task_id), plans its steps, marks it …

Start work in one call: files a new task (or takes an existing one with task_id), plans its steps, marks it in progress and starts the first step. Use this whenever the person asks for something: it puts the request on their board with a checklist and a progress bar. Returns the task id, the numbered steps with ids, the step now running, project notes and a cursor for taskhold_updates. Every event of the call (created, planned, started) carries the agent label. On a task already under way it appends the steps. Fails without title or task_id, on an unknown task_id (get one from taskhold_list) or on a step (begin its parent, or taskhold_start the step).

stepsstring | object[]optionalThe plan, in order, e.g. ["Read the code", "Write the migration", "Add tests"]. Omit for a one-step job.
descriptionstringoptionalDetails (markdown), e.g. the person's request in full
prioritystringoptionalPriority of a new task (default medium) One of: low, medium, high, urgent
labelsstring[]optionalLabels for a new task, e.g. ["bug", "refactor"]
agentstringoptionalLabel shown to the person: "<client> in <repo folder>", e.g. "Claude Code in api-server" ("Claude Code" outside a repo).

taskhold_blockcan modifyMark a task (or step) blocked when you can't continue without the person (a decision, missing info, access). …

Mark a task (or step) blocked when you can't continue without the person (a decision, missing info, access). Returns the question and the exact taskhold_updates call to wait with. Write the reason as one question they can answer from the board in a line, e.g. "Decide: drop the legacy column or keep it nullable?". When the answer is a choice, pass 2-4 short options (with recommended and if_no_answer): the person answers with one tap and the reply reads Reply to "<question>": chose "<option>". The board shows it under Needs you. Wait for the reply with taskhold_updates {task_id, since, wait: 50}; keep working on anything that doesn't depend on it meanwhile. If the reply doesn't settle it, block again with a narrower question; don't guess. Blocking an already-blocked task asks the new question instead, and the earlier question stays in the task's history; an unknown task_id fails with "Task not found".

ParameterTypeDescription
task_idstringrequiredThe ID of the task to block
reasonstringrequiredOne answerable question, e.g. "Approve: deploy the migration to staging now?"
optionsstring[]optional2-4 short choices shown as buttons, e.g. ["Postgres", "SQLite", "Ask me later"]. Omit for an open question.
recommendedintegeroptionalIndex into options of the one you recommend (0 = the first). Marked on the board.
if_no_answerstringoptionalWhat you will do if nobody answers, e.g. "I'll use SQLite and keep going in 30 min."

Example call (required arguments only, placeholder values):

{
  "method": "tools/call",
  "params": {
    "name": "taskhold_block",
    "arguments": {

taskhold_completecan modifyMark a task or step done, with a summary of what you did and, optionally, a structured outcome: files changed …

Mark a task or step done, with a summary of what you did and, optionally, a structured outcome: files changed (with +/- line counts), checks run (pass/fail/skip), links (PR, commit, branch, deploy, doc), follow-up task ids, risks and how the person can verify it. The person sees it as a What changed card; a step's outcome rolls up to its task. When the person should look at the work, pass needs_review: true with outcome.verify (how you checked it): the task lands in their Ready for review queue. Completing a step tells you the next one; start_next: true also starts it, and finish_task: true on the last open step closes the task too (with the same summary) in one call. For a step it returns steps done, the task's bar and the next step's id (or, after the last step, a reminder to complete the task). Completing a task closes its open steps. Repeating it on a task that is already done changes nothing and keeps the first summary (add more with taskhold_add_note); an unknown task_id fails with "Task not found", an invalid outcome fails without changing anything.

ParameterTypeDescription
task_idstringrequiredThe ID of the task to complete
summarystringoptionalWhat was done (and how you checked it). Markdown.
start_nextbooleanoptionalWhen completing a step, start the next step too (default false)
finish_taskbooleanoptionalWhen completing the last open step, also complete its task with this summary (default false)
outcomeobjectoptionalWhat changed, shown to the person as a What changed card (20 KB max). Every field is optional.
needs_reviewbooleanoptionalAsk the person to review the work: the task goes to their Ready for review queue (it still counts as done). Needs outcome.verify, a short "how I checked it" line. They approve it or request changes; both arrive in taskhold_updates (default false)
