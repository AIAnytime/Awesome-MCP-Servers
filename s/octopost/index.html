Set up in your client

Claude Code

Run this in a terminal:

claude mcp add --transport http octopost https://octopost.ink/mcp

Claude Desktop

Open Settings → Connectors → Add custom connector and paste this URL:

https://octopost.ink/mcp

Or bridge it through mcp-remote in claude_desktop_config.json (needs Node.js):

{
  "mcpServers": {
    "octopost": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://octopost.ink/mcp"
      ]
    }
  }
}

Cursor

Add to Cursor

Or add it to ~/.cursor/mcp.json (or .cursor/mcp.json in a project):

{
  "mcpServers": {
    "octopost": {
      "url": "https://octopost.ink/mcp"
    }
  }
}

  "servers": {

code --add-mcp '{"name": "octopost", "type": "http", "url": "https://octopost.ink/mcp"}'

{

If it does not connect

  • Restart the client after editing a config file, and keep keys out of files you commit.
  • If the tools do not appear, open the client's MCP log: a 401 means the credentials were not accepted, and a timeout means the server did not answer.

add_feedcan modifyexternal accessTurn an RSS or Atom feed (a blog, newsletter, changelog) into posts. Octopost reads it right away (a site …

Turn an RSS or Atom feed (a blog, newsletter, changelog) into posts. Octopost reads it right away (a site address works if the page links its feed), then checks it every 30 minutes by default. Each new item becomes a post from the template. The first check posts only the feed's latest item, so adding a feed never floods the account. By default (mode "hold") each new item waits for a person to approve it: Octopost emails the owner Approve / Reject / Edit links, so tell the user to check their email. With mode "queue" new items join the posting queue and publish in queue slots. At most 10 posts a day per feed; the same text to the same network within 7 days is skipped; a blocked term holds the post. Posts are shortened to fit each network (excerpt first, then title; the link stays whole).

modestringoptionalOptional. "hold" (default): each item waits for approval. "queue": items join the queue. One of: hold, queue

check_every_minutesnumberoptionalOptional. How often to check, 15 to 1440 minutes. Default 30.
accountsobject | stringoptionalOptional. Account to post as: {"twitter": "@handle"} or one handle. Default: each network's default.

queue_postcan modifyexternal accessAdd a post to your publishing queue. It will be published automatically during your active hours. Posts …

Add a post to your publishing queue. It will be published automatically during your active hours. Posts require platforms to be specified. HUMAN APPROVAL: set needs_approval=true when a person should review the post first (anything the user hasn't seen word for word). The post is held as "pending" and nothing is published until a person approves it. Octopost emails the account owner and any approvers one-tap Approve / Reject / Edit / Ask for changes links (batched, within about 5 minutes) and shows it in the dashboard. If they ask for changes, see resubmit_post. After queueing, tell the user: "It's waiting for your approval; check your email." You can't approve your own posts. The account owner can also set auto-approve rules, in which case the result says the post was auto-approved. The queue publishes posts in FIFO order (oldest first) at regular intervals during active hours (default: every 4 hours, 9am-8pm). Great for evergreen content and maintaining a regular posting cadence. Same platform limits and same options as create_post, which documents them in full.

Mark a post evergreen (or not). When the posting queue runs empty, Octopost posts an evergreen post again in the empty queue slot, picking the one that has rested longest.
